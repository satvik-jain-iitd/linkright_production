# DOC 06 — Resume, Positioning & Artifact Generation Engine

## 1. Purpose

This document defines how Linkright generates, optimizes, validates, and manages professional communication artifacts.

It specifies:

- resume generation architecture
- strategic positioning systems
- artifact generation philosophy
- expression generation
- width optimization integration
- layout-aware generation
- ATS optimization
- aggressive reframing rules
- placeholder systems
- metrics handling
- artifact lineage
- reproducibility
- generation constraints
- validation loops

This document defines the artifact generation layer of Linkright.

---

# 2. Artifact Philosophy

Linkright does not generate artifacts by filling templates blindly.

Artifacts should emerge from:

- canonical memory
- retrieval systems
- strategic positioning
- opportunity analysis
- identity consistency
- deterministic constraints
- layout constraints
- communication objectives

Artifacts are strategic communication systems.

Not merely formatted text outputs.

---

Supported artifact categories may include:

- resumes

- autofill responses
- interview-prep packs
- HR intro summaries
- networking messages

- future portfolio artifacts

Phase 1 primarily focuses on:
- resumes

---

# 4. Resume Philosophy

The resume is not a career archive.

It is:
- a strategic compression layer
- optimized for recruiter cognition
- optimized for hiring-manager trust
- optimized for fast signal extraction
- optimized for opportunity-specific positioning

The resume should:
- maximize signal density
- preserve readability
- preserve coherence
- preserve defensibility
- maintain strong identity consistency

---

# 5. Resume Optimization Hierarchy

When tradeoffs exist, resume optimization should generally prioritize:

1. Recruiter response rate
2. Strategic positioning strength
3. Hiring-manager credibility
4. Interview conversion potential
5. ATS compatibility
6. Authenticity and defensibility
7. Aesthetic polish

This hierarchy may evolve later.

---

# 6. Resume Constraints

The default phase-1 resume philosophy is:

```text
Strict one-page resume
```

The resume should:
- fill space efficiently
- maximize useful information density
- avoid wasted whitespace
- avoid low-value filler
- preserve readability
- preserve visual rhythm

Target:
- approximately 95% vertical space utilization

The system should aggressively optimize:
- line fitting
- section balance
- width efficiency
- semantic compression
- layout utilization

---

# 7. Width Optimization Philosophy

Width optimization is a first-class system concern.

The system should optimize:
- sentence length
- wording density
- line fitting
- semantic compression
- visual balance
- strategic readability

Important:
Width optimization is not purely deterministic.

The best results may emerge from:
- deterministic measurement systems
- semantic rewriting loops
- LLM-assisted rephrasing
- layout-aware optimization iterations

Examples:

```text
Original:
Improved onboarding efficiency for enterprise users

Optimized:
Improved enterprise onboarding efficiency
```

Or:

```text
Redesigned onboarding workflows for enterprise teams
```

depending on:
- width
- role emphasis
- recruiter clarity
- strategic fit

---

# 8. Layout-Aware Generation

Artifact generation should remain aware of:

- layout constraints
- available space
- section balance
- visual density
- line utilization
- section ordering
- whitespace economics

Generation and layout systems should cooperate.

The architecture should support iterative optimization loops:

```text
Generate
→ Measure
→ Rewrite
→ Validate
→ Re-measure
```

---

# 9. Section Strategy

The system should strategically decide:

- which sections appear
- section ordering
- section density
- number of bullets
- which bullets survive
- what each bullet communicates

Sections should not be static.

Different opportunities may require:
- different emphasis
- different compression strategies
- different narrative focus

---

# 10. Signal Density

Artifacts should maximize:

```text
Strategic signal per unit of attention
```

This means:
- semantically dense bullets
- compressed but readable wording
- high-value evidence selection
- low redundancy
- minimal filler

The system should prefer:
- strategically useful evidence
- high-leverage narratives
- recruiter-compressible language

---

# 11. Strategic Reframing

The system should support aggressive but defensible reframing.

Meaning:
- the same experience may be framed differently for different opportunities
- different signals may be emphasized
- interpretations may shift significantly

However:
- factual grounding must remain traceable
- semantic drift must remain bounded
- recruiter plausibility must remain preserved

Example:

Same experience may become:

```text
Cross-functional operational leadership
```

or:

```text
Enterprise onboarding optimization
```

or:

```text
AI-assisted workflow orchestration
```

depending on:
- opportunity
- role archetype
- strategic objective

---

# 12. Weak Experience Handling

Weak experiences should not necessarily disappear.

Possible strategies include:

### 12.1 Merge Into Broader Narrative

Example:

Small internship:

```text
Supported onboarding issue workflows
```

may merge into:

```text
Contributed to onboarding workflow optimization initiatives
```

inside a broader operational narrative.

### 12.2 Convert Into Skill Signal

Weak project becomes:
- AI workflow experimentation
- systems-thinking signal
- stakeholder exposure
- technical fluency indicator

### 12.3 Hide Strategically

If an experience weakens:
- positioning
- seniority perception
- strategic coherence

it may be excluded.

Selection should remain opportunity-aware.

---

# 13. Placeholder Metrics System

The system should support placeholder metrics.

Examples:

```text
Improved onboarding efficiency by X%
```

```text
Reduced manual workflow effort by Y hours/week
```

Placeholder variables may include:
- X
- Y
- Z
- A
- B
- C

The system may later:
- suggest realistic industry ranges
- ask for user confirmation
- perform replacement passes

This allows:
- strategic drafting
- progressive refinement
- interview preparation alignment

---

# 14. Metrics Integrity

The system should not silently invent metrics.

The system may:
- suggest possible metrics
- suggest realistic ranges
- infer metric categories

But:
- user confirmation remains important
- provenance should remain inspectable
- fabricated certainty should be avoided

---

# 15. ATS Optimization

ATS optimization should exist as a constrained subsystem.

ATS optimization should:
- improve keyword coverage
- improve role alignment
- improve discoverability

But ATS optimization should not:
- destroy readability
- reduce identity consistency
- create keyword spam
- weaken strategic coherence

ATS optimization is subordinate to recruiter clarity.

---

# 16. Recruiter Cognition Optimization

Artifacts should optimize for:
- fast scanning
- compressed understanding
- memorability
- trust formation
- signal extraction
- professional clarity

The system should assume:
- limited recruiter attention
- fast scanning behavior
- cognitive overload
- noisy hiring markets

Artifacts should therefore:
- reduce friction
- reduce ambiguity
- improve signal clarity

---

# 17. Identity Consistency

Resume generation should preserve coherent identity.

The system should avoid:
- fragmented positioning
- contradictory narratives
- random signal scatter
- inconsistent seniority signaling

The resume should feel like:
- one believable professional identity
- strategically compressed for the opportunity

---

# 18. Expression Generation

Expression generation should happen after:
- retrieval
- ranking
- strategic scoring
- opportunity analysis

Generation should operate inside:
- constrained semantic space
- retrieval-grounded context
- strategic objectives
- layout constraints

Generation should not behave like unconstrained writing.

- single-shot prompting
