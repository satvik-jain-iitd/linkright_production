# 31. Closed-Loop Learning Integration

The closed-loop learning system (DOC 24) is the primary feedback mechanism that makes long-term compounding concrete.

Every outcome event in the application lifecycle — response received, interview scheduled, offer made — feeds back into the signal weight layer that governs retrieval and resume generation.

How it connects to compounding:

- Outcome events are stored append-only. They accumulate across job search cycles, not just the current one.
- Signal weight updates are slow and bounded. A single outcome shifts weights marginally. A pattern across many outcomes shifts them meaningfully.
- Over multiple job searches, the system builds an evidence base of which signal combinations convert at which company types and role archetypes.

The compounding curve is non-linear. The first job search produces almost no learning signal — not enough outcomes. By the third or fourth cycle, the system has enough pattern data to materially improve retrieval quality, positioning coherence, and opportunity targeting.

This is the structural advantage of Linkright over point-in-time tools: the system becomes more accurate over time, not just more familiar.

Learning boundaries matter equally. The system must not overfit to rejection signals, narrow the user's identity based on a short losing streak, or collapse the full signal breadth to match the company type that converted most recently. Learning is directional but not brittle. Details are specified in DOC 24, sections 7 and 8.

# 32. Post-Offer Career Capital Accumulation

Compounding does not pause between offer acceptance and the next job search.

The post-offer layer (DOC 27) is where the most concentrated career capital accumulation happens. Inside a role, the user is generating evidence daily. Without a capture mechanism, most of that evidence decays before the next resume update.

How post-offer signals feed the compounding system:

- Weekly performance entries (wins, challenges, new responsibilities, feedback received) are stored as dated evidence nodes in the memory graph.
- These nodes strengthen signal confidence scores over time. A signal that appeared once in a prior resume becomes a signal with repeated, dated, contextual reinforcement.
- Promotion readiness analysis draws from the same compounding evidence pool. The system can identify signal gaps against a target level because it has been accumulating evidence continuously, not reconstructing it from memory at review time.

The asymmetry is important: career capital accumulated inside a role is far cheaper to capture in real time than to reconstruct later. The weekly rhythm (DOC 26) is the mechanism. The compounding benefit arrives during the next job search, when the evidence pool is deep and specific instead of shallow and vague.

Career pivot detection (DOC 27, section 9) is also a compounding-system output. The system surfaces misalignment between the user's stated archetype and their actual accumulated signals — not through a single event, but through a pattern across weeks of logged evidence.

# 33. Identity Evolution as a Compounding Layer

Professional identity in Linkright is not a static input. It is a slow-moving output of the compounding system.

The identity evolution architecture (DOC 28) closes the loop between accumulated signals and how the system positions the user going forward.

The compounding mechanism:

- Signals accumulate in the memory graph over months and years.
- When signal density crosses a threshold associated with a higher seniority band or a different archetype, the system surfaces an upgrade suggestion.
- If the user confirms, the identity profile updates. Future retrieval and resume generation use the new identity context.
- The previous identity state is preserved as a dated snapshot, which governs bullet framing for past roles. Retroactive inflation is structurally prevented.

Identity evolution is user-initiated (DOC 28, section 5). The system detects and suggests. The user confirms. This constraint is non-negotiable — identity is too consequential to update silently.

The archetype evolution graph (DOC 28, section 6) models common transition paths between PM subtypes. When accumulated signals match a known transition pattern, the suggestion is framed as natural evolution rather than inconsistency. This reduces friction for legitimate growth while maintaining the same confirmation gate.

# 34. The Full Career Lifecycle Loop

The compounding system spans the entire career lifecycle defined in DOC 00, Decision 1.

The loop:

```text
Job search
  → signal retrieval + artifact generation
  → application sent → employer response → interview → offer

Offer accepted
  → 30-60-90 onboarding (DOC 27)
  → weekly performance capture (DOC 26 + DOC 27)
  → signal compounding in memory graph (DOC 03)

In-role
  → promotion readiness tracking (DOC 27)
  → identity upgrade detection (DOC 28)
  → closed-loop outcome learning from prior search (DOC 24)

Career transition trigger
  → career pivot detection (DOC 27) OR identity upgrade confirmed (DOC 28)
  → next job search begins with materially stronger signal base

Next job search
  → retrieval uses compounded signal weights from prior outcomes
  → identity context reflects confirmed evolution
  → artifact quality is higher because evidence pool is deeper
```

Each pass through the loop strengthens the next pass.

The return curve is not linear. Early cycles produce modest improvement. Later cycles produce substantially better targeting, positioning coherence, and interview story quality — because the system has accumulated years of dated, context-tagged evidence rather than a single static profile snapshot.

This lifecycle loop is the architectural expression of the career navigation philosophy stated in section 2: operational leverage compounds over time.
