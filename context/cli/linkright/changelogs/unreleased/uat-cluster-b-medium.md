## [type: Fixed]

- **UAT #2 — Terminal noise (`[tokens] …` raw telemetry leaking into UX):** The two `print("[tokens] …")` sites in `llm/direct.py` (pre-send estimate + post-call usage) now gate behind a new `_debug_enabled()` helper that checks `LR_DEBUG` / `LR_VERBOSE` env vars. Default-off, so `linkright tailor` / `linkright profile create` no longer interleave raw telemetry with friendly progress verbs. Token data is still captured in the per-call `usage` dict and ends up in `16_telemetry.json`, so we lose nothing operationally. Opt in via `LR_DEBUG=1` when diagnosing pipeline LLM behaviour.

- **UAT #6 — `profile create` accepts any PDF / .md as a resume (certificates, cover letters):** Added `_looks_like_resume()` heuristic in `profile/cli.py` that runs BEFORE the 30-90 sec extract pipeline. Scores 4 deterministic signals — keyword density (≥3 of 'experience', 'education', 'skills', verb stems…), email regex, phone regex, ≥400 char body. If <3 signals pass, surfaces an interactive warning listing the specific missing signals; user can override (`y`) or cancel (`N`, default). Skipped under `--yes` (batch / scripted creation) and for markdown-augment mode (user already has a trusted profile). Empty / unreadable extracts pass through to avoid false-blocking — the existing PDF readability guard handles truly corrupt files.

- **UAT #9 — `--force` flag suggestion replaced with interactive 3-option picker:** When a profile already exists at `~/.linkright/profile/`, TTY users now see a `lr_select` picker with three choices: "Keep existing (cancel)", "Overwrite (wipe + re-ingest, existing data backed up)", "View existing first". Esc / cancel defaults to the safe "Keep" option. Non-TTY (CI / pipe) paths preserve the legacy `--force`-suggesting error so automation behaviour is unchanged. `--force` remains the explicit opt-in for unattended overwrite.

- **UAT #11 — "Paste resume text" option restored to `prompt_for_resume_source`:** The picker now offers two first-class options (file vs paste); selecting "Paste" drops the user into `questionary.text(multiline=True)` (Esc+Enter to submit). The captured body is materialised to a temp `.md` file inside a `linkright-paste-*` staging dir, then routed through the existing markdown-ingest path (Cluster A wired `.md` files via `-r` in PR #157). A scripted equivalent is exposed as `--from-paste`; the legacy `--paste` flag (previously a "Day 2 — coming soon" stub) now aliases the same path. Empty paste produces a clean error rather than running the pipeline. New tests in `test_uat_cluster_b_medium.py` + updates to `test_prompts.py` + `test_profile_create_guard.py`.
